# US Options Gamma Wall (SPY → US500)

로드맵 **§5**. 딜러 델타 헤지가 몰리는 행사가(벽)를 매 세션 기록하고,
다음 세션이 그 벽을 존중했는지 채점하는 **원장**이다. 실거래·알림 없음.

## 왜 이 전략인가 (한 문장)

> 딜러는 옵션 재고를 델타 헤지해야 하고, SPY 에서 그 규모는 1% 이동당 약 **$10bn —
> 하루 거래대금의 26%** 다. 그 헤지 주문이 몰리는 행사가가 지지·저항으로 작동한다.

같은 값이 BTC(Deribit)에서는 **0.16%** 다. 160배 차이. 그래서 크립토 옵션 흐름
전략이 죽었고(로드맵 T1·T2) 자원이 미국 옵션으로 왔다. **논리가 틀린 게 아니라
적용 시장이 틀렸던 것.**

## 레짐이 아니라 레벨이다

초안은 "GEX 부호로 페이드/추세 모드를 전환"하는 설계였다. T2 에서 폐기했다 —
콜+/풋− 규약의 GEX 부호는 시간에 따라 변하는 레짐이 아니라 **시장의 구조적 상수**다
(SPY 는 9세션 중 8세션 음수, BTC 는 1,379 스냅 전부 양수). 전환할 레짐이 없다.
남는 것은 부호와 무관하게 존재하는 **벽의 위치**.

## 계산

```
세션의 마지막 스냅샷(= OI 가 가장 신선한 것)에서
  strike 별 GEX = Σ γ · OI · 100 · S² · 0.01 · sign     (콜 +1 / 풋 −1)
  call_wall = argmax(GEX)  among strike > spot    (저항)
  put_wall  = argmin(GEX)  among strike < spot    (지지)
```

만기 가중은 따로 하지 않는다 — GEX 가 이미 OI 로 가중되므로 OI 40만짜리 일일 만기와
298만짜리 월물이 자동으로 제 몫만큼만 기여한다.

## 채점과 대조군

다음 세션 OHLC 로: `contained`(종가가 밴드 안), `touched_*`, `respected_*`(찍고 되돌림).

**반드시 대조군과 같이 본다** — 같은 폭을 스팟 기준 대칭으로 놓은 밴드.
벽이 '폭'이 아니라 '위치' 정보를 담아야만 대조군을 이긴다. `edge = 벽 − 대조군`.
edge 가 0 이면 벽은 아무 정보도 없고, 넓은 밴드가 잘 담긴 것뿐이다.

## 함정

- **세션 날짜 ≠ snapshot_ts 의 UTC 날짜.** 00:17 UTC 수집은 20:17 ET 라 이미 닫힌
  전날 세션을 담는다. 수집기 `fetch_session_date` 와 같은 규칙으로
  `last_trade_time`(ET) 에서 세션을 유도한다. UTC 날짜를 쓰면 전 구간이 하루씩 밀린다.
- **OI 는 하루 한 번 갱신**되고 장중 불변이다. 그래서 세션의 *마지막* 스냅을 쓴다.
- **`backfilled` 코호트를 절대 합치지 않는다.** 첫 실행은 과거를 소급 계산하므로
  백테스트다. 포워드 테스트는 이후 실시간 기록분뿐이다.
- 데이터 DB 는 `backtest_quant` (`US_OPTIONS_PG_URL` 로 재정의 가능).
  `us_options_gex_pin` 은 아직 존재하지 않는 `btc_backtest` 로 파생한다 — 별도 확인 필요.
